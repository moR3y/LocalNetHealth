# LocalNetHealth クイックスタート

このガイドでは、インストール後の5〜10分で監視画面を開き、必要に応じてスマートフォンや別PCから見られる状態にします。

LANアクセスとAdminの2段階認証は、必要な場合だけ設定する任意機能です。このPCだけで使う場合は、どちらも設定せずに始められます。

## 1. LocalNetHealthとは

LocalNetHealthは、Windows PCでネットワークの状態を継続して記録し、通信が不安定だったときに「その時に何が起きていたか」を確認しやすくする監視ツールです。

通信内容を解析するパケットキャプチャ、PCを遠隔操作するツール、クラウド監視サービスではありません。記録はこのPC内のSQLiteデータベースへ保存されます。

## 2. インストール

1. LocalNetHealthのインストーラーを起動します。
2. 画面の案内を確認してインストールします。
3. 完了画面の「通知領域で起動する」を選んだまま終了します。
4. Windowsの通知領域にLocalNetHealthアイコンが表示されることを確認します。

通知領域アイコンのメニューからダッシュボードやログを開き、LocalNetHealthを終了できます。

## 3. 初回起動

既定では **このPCだけで使うLocal Mode** で起動します。ブラウザが自動で開かない場合は、通知領域アイコンから「ダッシュボードを開く」を選ぶか、次のURLを開いてください。

`http://127.0.0.1:48721/`

Local Modeの通常閲覧にパスワードは必要ありません。同じPCを使える人を信頼する運用です。

## 4. まずダッシュボードを見る

- **概要**: 現在の健全性、収集状態、最近のアラートをまとめて確認します。
- **アラート**: ゲートウェイや新しく観測された機器など、確認が必要な変化を見ます。
- **デバイス**: 観測した端末のIPアドレスやMACアドレスを見ます。
- **設定**: LANアクセス、通知、バックアップ、認証などを管理します。

インストール直後は履歴が少ないため、一部のグラフや判定が「データなし」「履歴が不足しています」と表示されることがあります。監視を続けると情報が蓄積されます。

## 5. このPCだけで使う

スマートフォンや別PCから見ない場合は設定変更不要です。

- 接続先: `http://127.0.0.1:48721/`
- 利用範囲: LocalNetHealthをインストールしたPCのみ
- 既定の閲覧: パスワードなし

## 6. スマートフォンや別PCから見る

LAN Modeは、スマートフォンや別PCから見る場合だけ設定します。このPCだけで使う場合はLocal Modeのままでかまいません。

1. ダッシュボードで **設定 > LANアクセス** を開きます。
2. **LAN内からアクセス** を選びます。
3. 「推奨」と表示されたWi-FiまたはEthernetのアドレスを選びます。
4. 12文字以上のAdminパスワードを設定します。
5. 閲覧専用ログインも使う場合だけ、Adminとは異なるViewerパスワードを設定します。
6. **保存して再起動** を押します。
7. 再起動後に表示される接続URLをコピーするか、QRコードを読み取ります。
8. 同じLANまたはWi-Fiに接続した端末から開きます。

Adminパスワードは必須です。Viewerパスワードは任意で、未設定の間はViewerログインが無効になります。QRコードに入るのは接続URLだけです。パスワードやログイン情報は含まれません。

LAN Modeはインターネット公開用ではありません。公共Wi-Fi、ルーターのポート転送、公開サーバーでは使用しないでください。

## 7. ViewerとAdmin

| ロール | 用途 |
| --- | --- |
| Viewer | 概要、履歴、デバイス、アラートなどを閲覧します。設定変更はできません。 |
| Admin | Viewerの閲覧範囲に加え、LANアクセス、通知、バックアップ、認証、メンテナンスなどを管理します。 |

Public v1はユーザーIDを発行する複数アカウント方式ではありません。ログイン時にViewerまたはAdminを選び、それぞれに設定されたパスワードを使用します。

## 8. Adminパスワード

LAN Modeを有効にするときにAdminパスワードを設定します。パスワードは平文では保存されません。

忘れた場合はLocalNetHealthを停止してローカル認証リセットを行い、再設定します。詳細はユーザーマニュアルの認証・TOTP節を参照してください。

## 9. Viewerを後から有効にする

Viewerが不要なら、LAN Mode開始時にViewerパスワードを空欄のまま保存できます。後からAdminでログインし、認証設定からViewerパスワードを設定するとViewerログインが有効になります。

ViewerとAdminには異なるパスワードを設定してください。

## 10. 2段階認証(TOTP)は使いたい場合だけ

2段階認証はAdmin向けの任意機能で、通常利用に必須ではありません。既定は無効で、初回案内で **今は設定しない** を選んでも通常どおり使えます。

有効にする場合は、AuthenticatorアプリでQRコードを読み取り、6桁コードを入力します。有効化時に表示されるRecovery Codesは安全な場所へ保管してください。各Recovery Codeは1回だけ使用できます。Viewerには2段階認証を要求しません。

詳しくはユーザーマニュアルのAdmin向け2段階認証節を参照してください。

## 11. 通知とアラート

アラートはダッシュボードで確認できます。外部通知が必要な場合はAdminで **設定 > 通知** を開き、汎用Webhookを設定します。

LINE WORKS Incoming Webhook向けの送信形式も用意しています。実際の送信先でテストしてから使用してください。メール送信はPublic v1では利用できません。

## 外部DNS確認（既定オフ）

既定ではpublic hostnameのDNS確認を行いません。ゲートウェイ到達性は
このPC内の確認として維持されます。Adminが必要性を判断した場合だけ、
`config/local.toml`に次を追加して明示的に有効化します。

```toml
[collector]
external_dns_probe_enabled = true
external_dns_probe_target = "example.com"
external_dns_probe_interval_seconds = 300
external_dns_probe_timeout_seconds = 2.0
```

目的はDNS到達性の確認だけです。画面/API/履歴では`not_probed`、
`success`、`failed`を区別し、`not_probed`は失敗やアラートとして扱いません。
設定変更後はアプリを再起動してください。

## 12. アンインストール

- **KEEP（保持・既定）**: 監視履歴とエクスポートを残します。
- **DELETE（削除）**: LocalNetHealthが所有する監視履歴、エクスポート、設定、動作時に作られたデータを削除します。

通知先の秘密情報、Viewer/Admin認証情報、TOTP情報はどちらでも削除されます。同じフォルダにLocalNetHealthが所有しないファイルがある場合、そのファイルとフォルダは安全のため残ります。

一般質問や通常の不具合は[GitHub Issues](https://github.com/moR3y/LocalNetHealth/issues)へ。
セキュリティ問題は公開Issueへ投稿せず、管理者が有効化を確認した
[GitHub Private Vulnerability Reporting](https://github.com/moR3y/LocalNetHealth/security/advisories/new)を使用してください。

## 13. 困ったとき

- **ダッシュボードが開かない**: 通知領域にLocalNetHealthがあるか確認し、「ダッシュボードを開く」を選びます。
- **別の端末から開けない**: 同じWi-Fi、LAN Mode、保存後の再起動、推奨Wi-Fi/Ethernetアドレス、Windows Firewallのプライベートネットワーク設定を確認します。
- **表示されたLANアドレスで接続できない**: WSL、Hyper-V、Docker、VPNなどの仮想NICが選ばれている可能性があります。「推奨」のWi-FiまたはEthernetを選び直します。
- **TOTPコードが通らない**: PCとスマートフォンの日時を自動設定にし、新しい6桁コードで試します。
- **詳しい操作を確認したい**: [ユーザーマニュアル](USER_MANUAL.md) を参照してください。
